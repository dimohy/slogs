Slogs LLM Wiki: Agent를 위한 기억 검색 아키텍처

Slogs LLM Wiki는 사람이 남긴 결정과 선호를 검색 가능한 지식 자산으로 변환하고, Agent가 다음 작업에서 필요한 맥락을 먼저 회수하도록 설계된 시스템입니다.

Gemma: 의미를 숫자로 번역 pgvector: 유사 기억 검색 GraphRAG: 관계 단서 보강 Neo4j: 완전한 KG와 비교

핵심 메시지

Slogs LLM Wiki는 Neo4j 같은 완전한 지식 그래프가 아니라, Agent가 필요한 기억을 정확히 회수하도록 만든 GraphRAG 검색 인덱스입니다.

오늘 다룰 범위

Gemma, pgvector, 그래프 신호, Neo4j와의 차이를 각각의 역할과 경계 중심으로 정리합니다.

Conceptual flow

전체 구조는 네 단계로 볼 수 있습니다

1. 기록

사용자가 남긴 결정

“이 프로젝트는 배포할 때 AOT를 기본으로 쓰지 않는다” 같은 결정과 선호를 저장합니다.

2. 번역

Gemma가 의미 벡터 생성

문장의 의미를 768차원 벡터로 변환해 비교 가능한 형태로 만듭니다.

3. 탐색

pgvector가 유사 기억 검색

질문과 의미가 가까운 기억을 벡터 거리 기준으로 찾아냅니다.

4. 보정

태그와 카테고리로 재정렬

제목, 태그, 카테고리 같은 관계 단서를 더해 관련도가 높은 기억을 위로 올립니다.

이 네 단계가 Slogs LLM Wiki GraphRAG의 기본 구조입니다.

Why

왜 별도의 기억 검색 계층이 필요한가

1

세션 경계가 맥락을 끊습니다

개발 원칙, 배포 방식, 사용자 선호는 다음 세션에서도 동일하게 적용되어야 합니다.

2

표현이 달라지면 검색 품질이 떨어집니다

“AOT 쓰지 말기”와 “non-AOT 배포 정책”은 의미상 가깝지만, 단순 문자열 검색은 이를 놓칠 수 있습니다.

3

요약과 출처가 함께 필요합니다

현재 적용할 기억은 정리본으로 읽고, 최초 입력과 변경 이력은 출처로 보존합니다.

목표: Agent가 작업 전에 관련 맥락을 먼저 회수하도록 만드는 것

EmbeddingGemma

Gemma의 역할은 답변이 아니라 “의미 번역”입니다

여기서 Gemma는 생성형 답변 모델로 쓰이지 않습니다. 문장을 의미 벡터로 바꾸는 임베딩 모델입니다.

의미 공간

임베딩은 문장을 의미 공간의 좌표로 표현합니다. 의미가 가까운 문장은 좌표도 가깝게 배치됩니다.

입력

“Slogs 배포는 AOT를 기본으로 쓰지 않는다”

출력

768개의 숫자. 사람이 읽는 문장이 아니라, 데이터베이스가 거리 계산에 사용하는 좌표입니다.

운영

Slogs는 외부 API가 아니라 서버 안의 EmbeddingGemma를 GPU로 실행합니다.

핵심 표현: Gemma는 기억을 검색 가능한 의미 벡터로 변환합니다.

pgvector

pgvector는 의미 벡터에서 가까운 기억을 찾습니다

Gemma가 숫자 좌표를 만들면, PostgreSQL의 pgvector가 그 좌표끼리 얼마나 가까운지 계산합니다.

역할

정확한 제목 매칭이 아니라, 의미 벡터 사이의 거리 계산으로 후보 기억을 좁힙니다.

Slogs에서는

  • 모든 LLM Wiki 항목의 의미 좌표를 저장합니다.
  • 질문도 같은 방식으로 좌표로 바꿉니다.
  • 두 좌표가 가까운 항목을 후보로 가져옵니다.
정리: Gemma는 의미 벡터를 만들고, pgvector는 그 벡터로 의미상 가까운 기억을 찾습니다.
발표 표현: pgvector는 의미 벡터 검색을 PostgreSQL 안에서 수행하게 해주는 기능입니다.

GraphRAG

GraphRAG는 “의미 검색”에 “관계 단서”를 더하는 방식입니다

R

Retrieval

AI가 답하기 전에 관련 문서나 기억을 먼저 찾아옵니다. 이게 RAG의 기본입니다.

G

Graph

태그, 카테고리, 제목처럼 기억 사이를 이어주는 단서를 함께 봅니다.

+

Slogs 방식

벡터로 후보를 찾고, 그래프 단서로 “더 그럴듯한 기억”을 위로 올립니다.

GraphRAG는 그래프 DB 사용 여부가 아니라, 검색에 관계 신호를 결합하는 접근입니다.

Write path

Slogs는 저장할 때 두 종류의 인덱스를 만듭니다

현재 기억

Agent가 바로 적용할 수 있는 정리본입니다. “앞으로 이렇게 판단하라”는 형태로 남깁니다.

원문 출처

사용자가 실제로 말한 내용, 병합/수정 요청을 Raw Provenance로 보존합니다.

의미 인덱스

Gemma가 만든 768차원 의미 벡터입니다. 유사한 기억을 찾는 데 사용합니다.

관계 인덱스

태그, 카테고리 경로, 제목 핵심어 같은 단서입니다. 검색 결과 순위를 보정합니다.

기억 본문과 함께, 검색 품질을 높이는 인덱스를 같이 저장합니다.

Example

예: “Slogs 배포할 때 AOT 켜도 되나요?”

사용자 질문: “Slogs 배포할 때 AOT 켜도 되나요?”
Gemma

질문의 의미 벡터 생성

“AOT”, “배포”, “Slogs”가 들어간 질문을 비교 가능한 의미 좌표로 변환합니다.

pgvector

유사 기억 후보 검색

“일상 배포는 AOT 없이 진행한다” 같은 기억이 의미상 가까운 후보로 올라옵니다.

GraphRAG

관계 단서로 순위 보정

카테고리 slogs/deployment, 태그 non-aot가 있으면 더 강하게 봅니다.

Recall

회상 컨텍스트 반환

“일상 배포는 AOT 없이 진행한다”는 기억을 짧은 맥락으로 반환합니다.

이 흐름이 발표에서 가장 중요한 설명 포인트입니다.

Graph signal

여기서 “그래프”는 이런 관계 단서입니다

관계 단서는 검색 결과의 순위를 보정하는 메타데이터로 이해하면 됩니다.

단서 역할 예시
태그 기억에 붙은 짧은 라벨입니다. deployment, non-aot
카테고리 경로 기억을 넣어 둔 폴더 경로처럼 작동합니다. slogs/deployment/releases
제목 핵심어 제목에 들어간 중요한 말은 본문보다 강한 단서입니다. “Gemma 모델을 서버에서 실행한다”
본문 핵심어 기억 내용 안의 반복되는 단어도 보조 단서가 됩니다. “GPU”, “pgvector”, “GraphRAG”
발표에서는 이를 “검색 결과의 순위를 보정하는 관계 단서”로 표현합니다.

Knowledge graph?

완전한 지식 그래프인가요?

아니요. Slogs의 목표는 완전한 지식 그래프 구축이 아니라, Agent 기억 검색의 정확도를 높이는 것입니다.

Slogs에 있는 것

  • 기억마다 태그와 카테고리 경로가 있습니다.
  • 비슷한 의미를 찾는 임베딩 벡터가 있습니다.
  • 검색 결과를 보정하는 관계 단서가 있습니다.

Slogs에 없는 것

  • 사람, 회사, 프로젝트를 정식 엔티티로 모델링하지 않습니다.
  • 관계마다 타입과 방향을 정해 저장하지 않습니다.
  • 복잡한 그래프 탐색 질의 엔진은 없습니다.
정확한 표현: Slogs는 “완전한 지식 그래프”가 아니라 “그래프 신호를 붙인 RAG 기억 검색”입니다.
이 질문은 발표에서 꼭 짚고 넘어가는 게 좋습니다.

Neo4j difference

Neo4j와는 역할이 다릅니다

구분 Slogs LLM Wiki Neo4j식 지식 그래프
목적 Agent가 필요한 기억을 효율적으로 회수하게 하기 도메인 객체와 관계를 명확히 분석하기
저장 방식 PostgreSQL 안에 문서, 벡터, 관계 단서를 함께 저장 노드와 관계를 그래프 DB에 명시적으로 저장
관계 의미 태그/카테고리/제목이 같은 기억을 더 관련 있다고 봄 “A가 B를 사용한다”처럼 관계 타입과 방향이 있음
강점 운영이 단순하고 Agent 메모리 검색에 맞음 복잡한 관계 분석과 경로 탐색에 강함
정리: Slogs는 기억 검색 엔진에 가깝고, Neo4j는 관계 분석 엔진에 가깝습니다.

Agent interface

Agent에게는 search와 recall로 보입니다

search

후보를 찾을 때

넓은 주제에서 관련 기억 목록을 훑습니다. “어떤 기억이 있는지” 먼저 보는 용도입니다.

recall

답변에 바로 쓸 때

현재 질문에 필요한 기억을 압축해서 가져옵니다. Agent는 이 내용을 보고 답하거나 작업합니다.

품질 확인: 결과 수, 관련도 기준, 걸린 시간 같은 Retrieval Diagnostics가 함께 나와서 검색이 잘 됐는지 점검할 수 있습니다.
발표에서는 도구 이름보다 후보 검색과 맥락 회상이라는 역할로 설명합니다.

Wrap up

최종 정리

Slogs LLM Wiki는 사람이 남긴 결정과 선호를 Gemma로 의미 좌표화하고, pgvector와 관계 단서로 다시 찾아서, Agent가 맥락을 잃지 않게 만드는 시스템입니다.

Gemma

문장을 검색 가능한 의미 벡터로 변환합니다.

pgvector

숫자 좌표에서 가까운 기억을 찾는 검색 엔진입니다.

GraphRAG

태그, 카테고리, 제목 같은 관계 단서로 검색을 더 정확하게 만듭니다.
